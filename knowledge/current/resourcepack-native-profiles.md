## Defaults, ownership and compat

- The original preset implementation added no IDs. The native palette appends bit 57, while all **55** existing capabilities retain original keys and defaults, including `gaming.ancient_debris`, which is independent of the deleted debris world analyzer.
- A user must enable `scene.block_filter` for the Eater Clear preset and `others.handheld_size` for the Small Handhelds profile to affect rendering; the corresponding resource highlights must be enabled for the glow profile.
- All profiles update only the parent `SettingsDraft` and honor Save and apply, Esc/discard and persistence rules.
- The Eater preset resolves the built-in target list **only when chosen**, not during ticks/frames/startup, and ignores unregistered IDs. It is bounded by the existing Scene Filter limits (512 IDs, 48 KiB aggregate). The GPU sees an immutable compiled block set; no new per-frame lookups.
- This scope deliberately avoids implicit restoration of any runtime shader, CTM pack or global third-party preferences; the supplied pack files remain independently usable as packs.

## Verification gates

Common unit tests check: source inventory size/uniqueness, runtime registration predicate, identity/immutability, independent entity filter options, bounded input, Small Handhelds numeric profile, 19 resource toggles, and non-mutating settings drafts.

These tests establish the hide preset and existing controls only; they cannot prove opaque source-profile parity. Three-version GameTests must verify: actual Eater source preset selection and persisted contents, toggle/discard operation of resource and comfort presets, rendered block filter occlusion and chest/ore/handheld existing oracles, UI bounds in Japanese and English, resource reload, and JAR 200 KiB limit. Source-asset pixel parity and unsupported model/style effects are explicitly excluded.
